How contributions work

  1. Talk first for big changes

    Open a discussion or comment on the issue, so the change fits where MuhOS is going and nobody duplicates work.

  2. One change per pull request

    Fork the repository, branch from main, and keep each pull request to one feature or fix. Start each commit with a label such as [general] or [fedora].

  3. Run the checks

    CI builds the package, runs the install tests, and checks asset licences and lint. You can run the same checks locally:

    python3 -I tools/asset-inventory --strict
python3 -I tools/lint-baseline --check

  4. Show how you tested it

    Describe what you tried and include screenshots for anything visible. Performance claims need a benchmark.

Ground rules

  • Evidence over claims. Describe what you tested, not what you expect.
  • Licences matter. Every font, icon, sound and image needs a source and a redistributable licence. Apple's own artwork can't be used.
  • Respect upstream. MuhOS builds on Serpantinum by Illia Miroshnichenko; attribution stays.
  • Be kind. Assume good intent and help newcomers.

Contributions are licensed under the AGPL-3.0-or-later, like the rest of MuhOS. The full guide is in CONTRIBUTING.md.
