# VM benchmark: glass design (0.1.0-0.12) vs 0.1.0-0.11 (2026-10-25)

Same setup and method as `2026-10-19-vm-0.1-vs-0.8.md` (headless Fedora 44
VM, software rendering, `tests/vm/bench <dir> desktop 5 60 60`, medians with
[min-max]). Only the idle desktop scenario was run.

0.12 (built from the `[fedora] muhos 0.1.0-0.12` commit)
differs from 0.11 by: the frosted blur settings (size 10, 3 passes,
vibrancy, noise) and one blur rule covering the bar, panels, dock and welcome
screen; the glass dock; and the MuhOS launcher, notification banners,
on-screen indicator and lock screen. The launcher, banners and indicator are
created at shell start, so they are included in this idle measurement; the
lock screen, control centre and notification centre only when first used.

## Results (idle desktop)

| Metric | 0.1 baseline | 0.11 | 0.12 | 0.11 -> 0.12 |
|---|---:|---:|---:|---|
| quickshell CPU (one core) | 0.62% | 0.07% [0.07-0.07] | 0.07% [0.07-0.08] | no change |
| quickshell PSS | 487.0 MiB | 470.7 MiB [469.5-474.8] | 472.7 MiB [471.8-474.0] | ranges overlap: no claim |
| quickshell RSS | 558.4 MiB | 543.6 MiB | 545.7 MiB [545.4-547.6] | ranges overlap: no claim |
| Hyprland PSS | 174.6 MiB | 203.1 MiB [202.6-207.6] | 203.1 MiB [202.6-203.4] | no change |
| startup | 2.37 s | 2.41 s | 2.14 s [1.91-2.44] | ranges overlap: no claim |

## Findings

- The glass surfaces and the stronger blur cost nothing measurable at idle:
  shell CPU and memory and Hyprland's memory are where 0.11 left them.
- The earlier Hyprland regression (about +28 MiB against 0.1) is unchanged
  and still not isolated. A stronger blur (3 passes instead of 2) and one
  more blurred surface (the dock) did not move it, so neither the blur
  strength nor an extra blurred surface accounts for it.
- Not measured here: the cost of the blur while windows move under glass, on
  a real GPU. This VM renders in software and the desktop is idle.
